# ArtifactProof

## One-sentence thesis

ArtifactProof is a lightweight, local validation prototype for testing whether a required software artifact is actually responsible for the behaviour it was asked to implement, rather than merely existing alongside behaviour that passes conventional tests.

The repository also contains a reproducible synthetic heap/DSU benchmark for testing
whether multimodal models can recover exact data-structure states from rendered diagrams.

## Problem

Passing conventional software tests does not necessarily prove that an AI coding agent implemented the software artifact or architectural component explicitly requested by the user. A repository may contain a file or class with the right name, while the real behaviour is implemented elsewhere in the system.

## Motivating example

A requirement states:

"Create a reusable DiscountEngine module containing a calculate_discount() function and make CheckoutService use it for discount calculation."

A misdelivered implementation may include a DiscountEngine file and class that are structurally present, but the consumer still performs the discount calculation directly. Both versions can pass normal behavioural tests if the tested output is still correct.

## Research question

Can causal component ablation detect implementations that pass conventional tests while failing to realize the software artifact explicitly requested in the requirement?

## Why test passing may be insufficient

Unit and integration tests often validate externally visible behaviour, not the provenance of that behaviour. A system can satisfy the same I/O contract while bypassing the explicitly requested implementation artifact. This is especially relevant when code is generated by AI or assembled from ad hoc modules.

## ArtifactProof pipeline

1. Parse a structured requirement specification.
2. Analyze the repository.
3. Run the project's normal tests.
4. Validate the structural presence of the requested artifact and its consumer.
5. Copy the repository to a temporary location.
6. Neutralize the requested artifact in the copied repository.
7. Re-run relevant tests.
8. Compare before vs. after.
9. Compute the experimental Artifact Causal Score.
10. Produce an evidence-based verdict.

## Architecture

```text
Software Requirement
        |
        v
Requirement Specification
        |
        v
Repository Analysis
        |
        +--> Functional Validation
        |
        +--> Structural Validation
        |
        +--> Causal Artifact Ablation
        |
        v
Run relevant tests again
        |
        v
Compare before vs after
        |
        v
Artifact Causal Score
        |
        v
Evidence Report / Final Verdict
```

## Synthetic multimodal benchmark

The synthetic pipeline creates deterministic operation programs, executes every state
transition, renders each state as a PNG, asks a configurable vision model to recover the
state, and computes exact-match and field-level metrics.

```text
seeded programs -> heap/DSU traces -> PNG frames -> vision model -> metrics
```

Run the configured data-generation and rendering pipeline:

```bash
python -m artifactproof.synthetic.cli run --config experiments/synthetic_benchmark.yaml
```

Model evaluation is disabled in the checked-in configuration so the command is safe to
run without credentials. To evaluate a model, set `model.enabled: true`, configure its
HTTP endpoint, and optionally put its bearer token in
`ARTIFACTPROOF_MODEL_API_KEY`. The endpoint contract is documented in
[docs/synthetic-benchmark.md](docs/synthetic-benchmark.md).

Individual stages are also available:

```bash
python -m artifactproof.synthetic.cli generate --output build/programs.jsonl --examples 10 --seed 42
python -m artifactproof.synthetic.cli execute --input build/programs.jsonl --output build/traces.jsonl
python -m artifactproof.synthetic.cli render --input build/traces.jsonl --output-dir build/images
python -m artifactproof.synthetic.cli evaluate --input build/traces.jsonl --images build/images --output build/evaluations.jsonl --endpoint http://localhost:8000/v1/predict --model local-vision-model
python -m artifactproof.synthetic.cli metrics --input build/evaluations.jsonl --output build/metrics.json
```

The checked-in seed-42 structural benchmark contains 200 programs and 1,308 transitions.
All 1,508 states passed heap/DSU invariant checks. Reproduce it with:

```bash
python experiments/run_synthetic_benchmark.py
```

See [results/synthetic_benchmark_summary.json](results/synthetic_benchmark_summary.json)
for the generated summary. These are generator-integrity results, not vision-model
accuracy claims.

## Artifact Causal Score

ArtifactProof implements an experimental metric called the Artifact Causal Score (ACS). This is not claimed to be an established research metric or universal standard. It is an experimental metric used by this prototype.

For the MVP:

ACS = number of previously passing relevant tests that fail after artifact ablation / number of relevant tests that passed before ablation

Example:

- 8 relevant tests pass before ablation
- 6 of those fail after ablation
- ACS = 6 / 8 = 0.75

If ACS = 0, disabling the requested component did not affect tested behaviour. This is flagged as suspicious.

## ArtifactProofBench

ArtifactProofBench includes five small Python software-engineering tasks:

- DiscountEngine
- AuthService
- CacheManager
- ValidationService
- ParserService

Each benchmark task contains:

- a requirement specification;
- a correct implementation;
- a misdelivered implementation;
- a pytest suite.

## Experimental methodology

The benchmark runner executes each task against both the correct and misdelivered versions. It records:

- baseline results before any mutation;
- structural validation status;
- post-ablation results;
- ACS and verdicts;
- whether the detection matched the expected outcome.

## Failure cases

ArtifactProof is intentionally conservative about interpretation. It does not claim that a single score is scientific proof. Some common failure cases include:

- causal ablation may produce false positives;
- some component behaviour cannot be isolated cleanly;
- software components may be legitimately redundant;
- integration tests may not cover every required behaviour;
- causal dependency does not establish complete semantic correctness.

## Limitations

This prototype has several honest limitations:

- current MVP supports Python only;
- requirement specification is currently structured rather than fully natural-language based;
- static analysis is intentionally lightweight and not perfect;
- dynamic dispatch and framework-heavy repositories may evade the current checks;
- the current evaluation is best seen as additional evidence rather than proof.

## Future work

Planned extensions include:

- comparison across different coding agents.

## Research positioning

ArtifactProof is a prototype for causal validation of AI-generated software components. It is designed to answer a narrow but practically important question: when a required artifact is structurally present and a repository passes ordinary tests, does the tested behaviour actually depend on that artifact?

The tool is not a correctness oracle. It provides additional evidence about causal ownership instead of a guarantee of semantic correctness.

## Reproducibility

To reproduce the benchmark locally:

```bash
python -m pip install -r requirements.txt
python -m pytest -q
python experiments/run_benchmark.py
```

The project writes machine-readable results to [results/results.json](results/results.json) and [results/results.csv](results/results.csv).

> ArtifactProof does NOT prove program correctness. It provides additional evidence about whether a required software artifact is causally involved in the behaviour it was requested to implement.
